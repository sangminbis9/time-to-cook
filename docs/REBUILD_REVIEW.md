# Time to Cook — 새 구현 검토

2026-10-16. `PLAN.md`와 첨부된 재제작 요청을 기준으로 `game/rebuild/`에 새 게임을 작성했다. 기존 게임 코드를 가져오지 않았으며 기존 폴더는 `.gdignore`로 실행·내보내기에서 제외했다. 기존 `project.godot`, README, 에디터 캐시는 `.tools/legacy-before-rebuild/`에 보관했다. 기존 한글 폰트만 OFL 라이선스와 함께 재사용한다. 사용자가 수정해 둔 PLAN 및 import 변경은 되돌리지 않았다.

## 구현

- 공통 권한 모델: 싱글/2인 ENet가 동일 `world.gd` 커맨드를 사용한다. 피어별 요청 순번, 검증된 위치·단계·금액·재고·예약으로 중복 거래와 음식 중복 제출을 차단한다. 게스트 캐릭터는 재접속 토큰과 연결되며 후보의 미공개 특성과 미구매 시장 실값을 게스트에게 전달하지 않는다.
- 20Hz 세계 시계, 준비/09–21시 720초/21–22시 60초/정산. 부재 매장은 0.5초 배치로 같은 고객·직원 상태를 전진시키며 화면 전환 때 추가 매출을 생성하지 않는다. 두 플레이어 준비 완료, 30일 달력, 일일 자동 저장.
- 4종 캐릭터, 방향 이동·충돌·슬롯·놓기·공동 픽업·개인 연구·능력. 생닭→칼질→튀김옷→튀김 품질창→담기·양념→서빙. 7개 메뉴, 실제 원재료와 용기 소모, 비가열 냉장 보존, 마감 폐기.
- 홀/포장 고객 입장·이동·FIFO 테이블 대기·접수·메뉴 타이머·식사·퇴장·오염. 테이블별 지속 청소 진행도, 플레이어 2명과 청소 직원의 합산 작업, 매장/브랜드 평판과 수요.
- 7직종 직원: 실제 이동과 예약 기반 전처리/조리/서빙/계산/청소/정비/매니저 작업. 등급·임금·계약·주간 후보·재모집·월간 휴가·질병/결근·포상·관계·요구·만족도·퇴사. 복리후생 8종의 실제 방문과 이용 비용.
- 차량 5종, 구매·판매·주차 확장, 차종별 속도·가속·정차, 뒷문·주차장·90타일 직접 운전·마트·한정 소매 재고·3배 가격·화물·귀환 하역·22시 복구. 한 명이 운전할 때 다른 매장 운영이 지속된다.
- 16도시 지도, 진출/방문/폐점/30일 재진출 제한, 시장 정보 스냅샷·사기·상위 보고서 할인, 일일 지역경제/날씨. 공용 원화 자금·최대 3건 대출·이자/만기/연체·연구·광고·가격/메뉴·준비 자동발주.
- 타일 건설·이동·회전·철거·바닥·냉장 확장·다층·계단·접근성 flood fill. 설비 사고 7종, 직접 대응/정비/예방 시설. 원본 픽셀 스프라이트, 합성 음악 2곡과 SFX, 타이틀 원화, 한국어 UI·도움말·키 변경·음량·전체화면·고대비 강조.
- 버전 2 JSON 봉투·해시·임시 쓰기 검증·백업/rename·백업 복원, 3슬롯과 덮어쓰기 확인. 기존 게임 저장은 새 저장으로 오인해 읽지 않는다.

## 확인한 증거

- 탑다운 아트 개편: `jp_art.json`으로 260개 리소스를 로드한다. 16도시 × 8종 가구는 도시별 원화가 적용되며 건설 미리보기와 신규 가구도 동일한 매핑을 사용한다. `release/visual-refresh/results.json`은 16도시 렌더 및 128가구 연결 검사, `all-city-furniture.png`는 원화 비교표다. 중복 이미지 해시도 검사했다. 통합 47항목과 UI 13화면을 다시 통과했고, 새 Windows 실행 파일에서 GPU 렌더 캡처 및 종료 코드 0을 확인했다. `exported-render.txt`와 `exported-render-errors.txt`에 실행 로그를 보존했다.

- `release/smoke-results.json`: 통합 항목별 결과. 원재료부터 실제 조리·홀 서빙·협동 청소·차량 왕복·소매 비용·하역·폐기·직원·연구·일본 진출·다층/엘리베이터·차량 개선·보험·저장 복원.
- `release/network-host.json`, `release/network-guest.json`: 별도 두 Godot 프로세스. 게스트가 운전·구매·귀환·하역하는 동안 호스트 시계 진행. 동일 RPC 재전송이 중복 결제되지 않고 최종 게스트 스냅샷에 재고 반영. 테스트 시간을 제한하기 위해 호스트의 정규 시뮬레이션 스텝만 빠르게 진행했다.
- `release/ai-results.json`: 소유자가 주차장에 있는 동안 7직종 직원이 자동화하고 복리후생 시설을 사용했다. 300 게임분의 단일 표본이며 장기 밸런스 결과로 해석하지 않는다.
- `release/ui-results.json`: 새 슬롯→캐릭터→게임, 13개 패널 구성/크기, 실제 Godot 입력 이벤트로 WASD 이동. 렌더 스크린샷은 엔진 출력이다. 사람이 마우스로 모든 경로를 검수했다는 의미는 아니다.
- Windows x86_64 공식 4.7-stable 템플릿 내보내기와 실행 파일 시작. GPU는 Intel Iris Plus / OpenGL 3.3. 초기 sandbox 네트워크·내보내기 temp 제약은 필요한 접근을 허용한 실행에서 확인했다.
- 배포판의 폴더 열거에서 import된 스프라이트가 빠지는 문제를 발견해 `art_manifest.json` 기반 로딩으로 수정했다. 수정된 실행 파일에서 주방을 직접 렌더한 증거는 `release/exported-proof/gameplay.png`, 로그는 `release/exported-render.txt`이다. 이 렌더 실행은 종료 코드 0이며 오류/경고가 없었다. 매우 짧은 headless 강제 종료에서는 종료 시점 리소스 정리 경고가 남아 `windows-startup.txt`에 그대로 보존했다.

## 남은 출시 검토와 구현 한계

- 장시간 7/30/90일 수익 밸런스, 외부 WAN 지연·유실·공유기별 연결, 다양한 PC/GPU/화면 배율은 이번 짧은 검증에 포함하지 않았다. 사용자가 반복 QA를 제한했다.
- 부재 매장은 같은 FSM을 0.5초 단위로 묶는다. 대규모 별도 분석 모델이나 수천 NPC를 처리하는 시스템은 아니다. 바닥은 `TileMapLayer`, 고객·직원은 저장 가능한 데이터와 그리기 계층, 캐릭터 충돌은 서버의 타일/사각형 검증으로 구현했다. 모든 배우를 `CharacterBody2D`로 만드는 구조와는 다르다.
- 16도시는 경제·시장·조건, 3종 매장 면적 및 도시별 8종의 가구 원화를 사용한다. 도로는 같은 90타일 구조의 지역별 배경 변형이며, 도시마다 수작업한 대형 맵이나 복잡한 교통 물리는 없다. 다층 이동은 계단과 엘리베이터, 보험은 하루 단위 사고 손해 보장, 차량 개선은 3단계 속도/적재 확장으로 구현했다.
- 직원 이동은 타일 BFS와 예약을 사용한다. 캐릭터끼리 부드럽게 비켜서는 고급 군중 동작은 없다. 관계 이벤트와 매니저 배분은 간소화했다. 고객 그룹 인원은 데이터에 있으나 한 주문/한 방문객 그림으로 표현한다.
- 픽셀 타일/스프라이트는 내장 이미지 생성 도구로 만든 원화를 타일 격자에 정리한 것이다. 이전 도형 기반 스프라이트는 현재 렌더러에서 사용하지 않는다. 걷기는 방향별 원화에 1px 보행 이동을 적용하며 팔다리를 별도 제작한 애니메이션은 아니다. 상업 출시 전 아트 디렉션·연출·사운드 반복감에 대한 사람의 검토가 필요하다.
- 한국어 원문 카탈로그와 `tr` 연결 지점이 있으나 영어 등 추가 언어 번역은 제공하지 않는다. Steam 로비/릴레이/클라우드/업적 SDK, 게임패드 전용 UX, Steam Deck 검증, 코드 서명은 포함되지 않는다.
- Steam 제출용 검토 자료와 실행 빌드이지 Valve 인증·출시 승인 결과가 아니다. 부족한 부분을 완료했다고 표시하지 않았다.
